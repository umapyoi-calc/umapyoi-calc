UMAPYOI CALC - HANDOFF RAPIDO MULTI-PC
Last updated: 2026-08-04

0) TL;DR
- Trabaja siempre dentro de: umapyoi-calc/
- Setup nueva PC:
  1. npm install
  2. crear .env.local
  3. firebase login --reauth
  4. npm run dev
- Sincronizar datos Firebase desde JSON/imagenes: npm run sync:data
- Publicar todo (datos + build + hosting): npm run publish:auto

1) Estructura del workspace
- old/
  - Fuente legacy de datos e imagenes locales.
  - JSON principal: old/src/data/character_data.json y old/src/data/card_imgs.json
- umapyoi-calc/
  - App activa (React + TS + Vite) conectada a Firebase.
  - Todos los comandos se ejecutan aqui.

2) Identidad del proyecto Firebase
- Firebase project id: umapyoi-calc-dev
- Bucket esperado: umapyoi-calc-dev.firebasestorage.app
- Hosting URL: https://umapyoi-calc-dev.web.app

3) Setup en una computadora nueva (one-time)
1. Instalar Node.js 22+ y npm 11+
2. Instalar Firebase CLI:
   npm install -g firebase-tools
3. Entrar al proyecto correcto:
   cd C:\ruta\a\workspace\umapyoi-calc\umapyoi-calc
4. Instalar dependencias:
   npm install
5. Crear .env.local en umapyoi-calc/ con:

   VITE_FIREBASE_API_KEY=TU_API_KEY
   VITE_FIREBASE_AUTH_DOMAIN=TU_AUTH_DOMAIN
   VITE_FIREBASE_PROJECT_ID=umapyoi-calc-dev
   VITE_FIREBASE_STORAGE_BUCKET=umapyoi-calc-dev.firebasestorage.app
   VITE_FIREBASE_MESSAGING_SENDER_ID=TU_MESSAGING_SENDER_ID
   VITE_FIREBASE_APP_ID=TU_APP_ID
   VITE_FIREBASE_MEASUREMENT_ID=TU_MEASUREMENT_ID

6. Login Firebase:
   firebase login --reauth
7. Verificar proyecto activo:
   firebase use

4) Comandos diarios
- npm run dev
- npm run build
- npm run lint
- npm run preview

5) Flujo de datos Firebase (automatizado)
Requiere service account para escritura (scripts admin).
Nota: npm run upload:storage -- -- --dry-run y npm run seed:firestore -- -- --dry-run validan sin escribir y sin credenciales.
Con npm 11 en PowerShell usa doble separador para flags: -- --

PowerShell (por sesion):
$env:FIREBASE_SERVICE_ACCOUNT_PATH="C:\ruta\a\tu\service-account.json"
$env:FIREBASE_STORAGE_BUCKET_NAME="umapyoi-calc-dev.firebasestorage.app"

Opcional si cambias origen local:
$env:PUBLIC_DIR="C:\otra\ruta\public"
$env:DATA_DIR="C:\otra\ruta\data"

# Compatibilidad legacy:
$env:OLD_PUBLIC_DIR="C:\otra\ruta\public"
$env:OLD_DATA_DIR="C:\otra\ruta\data"

Scripts disponibles:
- npm run upload:storage
  - Sube imagenes de public/{main,outfits,racewear} a Storage (fallback legacy: old/public).
  - Flags utiles: --dry-run, --public-dir, --folders, --bucket, --service-account.
- npm run check:storage
  - Dry-run de upload:storage (valida archivos sin subir).
- npm run seed:firestore
  - Lee JSON de src/data (fallback legacy: old/src/data) y actualiza colecciones characters y cards.
  - Flags utiles: --dry-run, --only characters|cards, --strict, --data-dir, --characters-file, --cards-file.
- npm run check:seed
  - Dry-run de seed:firestore (valida JSON sin escribir).
- npm run check:data
  - Ejecuta check:storage + check:seed.
- npm run sync:data
  - Ejecuta upload:storage + seed:firestore.
- npm run deploy:hosting
  - Build + deploy de hosting.
- npm run publish:auto
  - Ejecuta sync:data + deploy:hosting.

6) Flujo recomendado para trabajar en varias PCs
1. Pull de cambios
2. npm install (si cambio package-lock o package.json)
3. Cargar variables de sesion para scripts admin (si vas a sincronizar datos)
4. npm run sync:data
5. npm run dev para validar
6. npm run publish:auto cuando quieras publicar

8) Troubleshooting rapido
- Error npm ENOENT package.json:
  - Estas en la carpeta incorrecta.
  - Solucion: entrar a umapyoi-calc/ antes de usar npm.

- Error firebase use must be run from a Firebase project directory:
  - No estas parado donde existen firebase.json y .firebaserc.
  - Solucion: entrar a umapyoi-calc/.

- Error The specified bucket does not exist:
  - Bucket mal escrito.
  - Solucion: usar umapyoi-calc-dev.firebasestorage.app.

- Error Firebase 401 / failed to list projects:
  - Token expirado.
  - Solucion: firebase logout y firebase login --reauth.

9) Seguridad
- No subir service-account.json al repo.
- No subir .env.local al repo.
- La service account solo se usa en scripts admin (nunca frontend).
